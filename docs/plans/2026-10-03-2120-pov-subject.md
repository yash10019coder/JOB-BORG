# Subject: JobBorg Profile System - 3 Critical Architectural Decisions

## Project Context
JobBorg is a Django 5 + Celery + Postgres/pgvector job matching platform. Users create profiles, get matched to jobs, and can auto-apply via Greenhouse. Current state: two separate pages (Profile + ExplicitAnswers) with overlapping fields.

## Decision 1: Profile ↔ ExplicitAnswers Relationship

### Current State
- **Profile model**: Structured per-country data (`visa_status_by_country` JSON dict, `citizenship_countries` JSON list, `salary_region_*` 7 dropdowns, `min_salary` integer)
- **ExplicitAnswers model**: Free-text answers (`work_authorization`, `sponsorship`, `salary_expectation` band, `other`)
- Two separate pages, user confusion about overlap

### Options
| Option | Description |
|---|---|
| **A: Profile = Source of Truth** | Profile drives auto-apply; ExplicitAnswers stores only overrides (delta) |
| **B: ExplicitAnswers = Source for Auto-Apply** | Auto-apply reads ExplicitAnswers exclusively; Profile only for matching |
| **C: Full Merge (Recommended)** | Eliminate ExplicitAnswers table. All auto-apply answers live on Profile as structured fields. ExplicitAnswers page becomes Profile Tab 2 view. |
| **D: Derivation with Divergence** | Profile → derives ExplicitAnswers; user can edit both; sync prompts on save |

### Evidence
- Migration 0009 already created `visa_status_by_country`, `citizenship_countries`, `salary_region_*`
- Auto-apply drafting currently reads both Profile + ExplicitAnswers
- Learning loop (Decision 3) writes to Profile fields
- ExplicitAnswers.OTHER is unused free-text

## Decision 2: Self-Learning Profile Loop Architecture

### Requirements
- Learn from: explicit edits, application questions, outcomes (Applied/Failed), match quality, review queue edits
- Optimize: reduce `unanswerable_required`, increase draft→applied, improve match quality
- Auto-learn low-risk (custom answers), suggest high-risk (salary, visa, citizenship)

### Options
| Option | Description |
|---|---|
| **A: Rule-Based Only** | SQL patterns: "3+ consistent answers → suggest" |
| **B: Embeddings + Clustering** | pgvector: embed questions, cluster, find consensus |
| **C: LLM-Based** | Periodic LLM: "Here are all Q/A/outcomes → what Profile updates?" |
| **D: Hybrid Rules + Embeddings (Recommended)** | Rules for structured (salary, visa), embeddings for custom questions |

### Evidence
- 65 work auth, 73 sponsorship, 47 salary, 310 location questions in drafts
- Custom questions: 30+ experience, 25+ tech, 20+ relocation, 15+ projects
- pgvector already in stack (Postgres + pgvector)
- sentence-transformers available (all-MiniLM-L6-v2, 384-dim)

### Execution Contexts (All Three)
1. **Incremental hook**: Post-draft outcome (APPLIED/FAILED/EXCLUDED)
2. **Daily batch**: Celery Beat 3 AM, re-cluster, recompute confidence
3. **On-demand**: "Improve my profile" button

### Risk Gate
- Low-risk (custom_answers, high-confidence) → auto-apply (confidence ≥0.85)
- High-risk (salary, visa, citizenship, locations) → suggest only (confidence ≥0.70)

## Decision 3: Resume Parsing → Profile Integration

### Experiment Results (5 test resumes)
| Parser | Contact | Skills | Experience | Education | Projects | Name | Summary |
|---|---|---|---|---|---|---|---|
| Rule-Based | 1.00 | 0.78 | 0.20 | 0.93 | 0.89 | 0.00 | 0.00 |
| Local LLM (gemma2:2b) | Failed - crashes, ANSI output | | | | | | |
| Cloud LLM (GPT-4o-mini) | Not tested | | | | | | |

### Options
| Option | Description |
|---|---|
| **A: Onboarding Wizard Only** | First resume upload → parse → review → save |
| **B: Re-sync Button** | User clicks "Refresh from Resume" anytime |
| **C: Background Re-parse** | Periodic re-parse, silent updates |
| **D: All Sources (Recommended)** | Resume (rule + cloud LLM) + GitHub API + LinkedIn scrape, Onboarding + Re-sync |

### Evidence
- Rule-based excels at contact, education, projects, skills (keyword match)
- Local LLMs (gemma2:2b, gemma4:e2b) crash on structured JSON extraction
- job-agent has `resume_inventory.json` schema mapping perfectly to Profile fields
- GitHub API: languages → target_tags, topics → custom_answers, repos → portfolio
- LinkedIn: headline, location, skills (public scrape, fragile)

### Phases
1. Rule-based parser (Week 1-2)
2. Cloud LLM enhancement - OpenRouter GPT-4o-mini (~$0.001/resume) (Week 3-4)
3. GitHub API enrichment (Week 5)
4. LinkedIn enrichment (Week 6)
5. Onboarding wizard + Re-sync button (Week 7-8)

3. **Resume Parsing**: Cloud LLM fallback (GPT-4o-mini) for experience extraction — is $0.001/resume acceptable? Should we skip local LLMs entirely given experiment failures?
